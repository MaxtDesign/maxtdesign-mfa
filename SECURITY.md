# Security Policy

## Supported versions

MaxtDesign MFA follows a rolling-release model on WordPress.org. Only the latest published version
receives security fixes. Always run the most recent release.

| Version | Supported |
| ------- | --------- |
| Latest stable (0.1.x) | Yes |
| Older releases | No |

Version 0.1.x is a development build that has not had its security review yet. Do not rely on it
to protect a live site.

## Who publishes this plugin

This plugin is published on WordPress.org by the account **`slaacr`**, which is MaxtDesign. The
account name predates the brand, and WordPress.org does not support renaming accounts, so the two
names differ. Anything published under `slaacr` is ours. We state this rather than leave you to
work it out, because being able to tell who publishes a plugin is the whole point of a security
contact.

## Reporting a vulnerability

If you believe you have found a security vulnerability in this plugin, please report it privately.
**Do not open a public GitHub issue, pull request, or WordPress.org support thread for security
matters.**

Email: **security@maxtdesign.com**

Please include: a description of the vulnerability and its potential impact; the plugin version
affected; step-by-step reproduction (proof-of-concept code, requests, or screenshots where
relevant); any suggested remediation.

## What to expect

- **Acknowledgement** within 3 business days.
- An initial assessment and severity classification within 7 business days.
- Coordinated disclosure: we will agree on a disclosure timeline with you and credit you in the
  changelog unless you prefer to remain anonymous.
- A patched release pushed to WordPress.org as soon as a fix is validated, with an
  `== Upgrade Notice ==` entry advising users to update.

## Scope

In scope: vulnerabilities in this plugin's own code, including authorization and capability
bypasses, stored or reflected XSS, SQL injection, CSRF on state-changing actions, and unsafe
handling of user input or uploaded files. For an authentication plugin that explicitly includes:
any way to obtain a logged-in session without passing the required second factor, bypasses of
the per-role policy, weaknesses in the TOTP, recovery-code, email-code or passkey (WebAuthn)
verification, leaks of secrets or of the moved login address through the plugin's own output,
and flaws in the lockout or rate limiting.

Out of scope: issues in WordPress core, other plugins or themes, the hosting environment, or the
site's own configuration; social engineering; and reports generated by automated scanners without
a demonstrated exploit path. The moved login address is obscurity, not a security boundary; a
report that the address can be discovered is only in scope if the plugin itself discloses it.

Please do not test against a site you do not own.
